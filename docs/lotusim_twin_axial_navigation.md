# 单障碍、无流 LOS 闭环导航验收

独立入口：`ros2/twin_axial_navigation/`。复用原有 A*、碰撞检查路径捷径、LOS、当前 PID、分配后抗饱和，以及 `uuv_twin_axial_v2` 的双推进器分配和 xdyn 动力学。旧模型、算法源码、参数文件及冻结数据不修改。

## 启动：PowerShell → NixOS

1. 打开 PowerShell，进入 NixOS：

```powershell
wsl -d NixOS
```

2. 进入项目目录：

```bash
cd /mnt/c/Users/刘松原/uuv_simulator
```

3. 首先运行一次基准 P0：

```bash
bash ros2/twin_axial_navigation/run-nix.sh run --case P0 \
  --output "artifacts/twin_axial_navigation/P0_$(date +%Y%m%d_%H%M%S)"
```

程序自行启动 LOTUSim、xdyn 和通信网关，运行真实闭环，结束后自动清理自己的进程。默认无 GUI；不需要另开 LOTUSim 网页或 Gazebo。首次可能下载 Nix 依赖。本入口使用单独的 Nix 环境，增加规划器需要的 Shapely，保留既有 LOTUSim/xdyn 版本锁定。

不要与旧开环、PID、motion 或其他占用 12356/12357 端口、ROS domain 74 的试验同时运行。输出目录必须是新目录，已有目录不会覆盖。中途 Ctrl+C 属于未完成试验，不会判为通过。

4. 完整验收：五组初始状态，加一次 P0 重复试验：

```bash
bash ros2/twin_axial_navigation/run-nix.sh suite \
  --output "artifacts/twin_axial_navigation/suite_$(date +%Y%m%d_%H%M%S)"
```

等待最后的 JSON；每个子试验也会输出自己的结果。完整套件需数分钟。最终应看到 `passed: true`、`all_runs_safe: true`、`repeatability.passed: true`。五组初始条件的正式最低通过率为 4/5，且 P0 必须通过；`all_runs_passed` 额外报告全部六次是否通过。

5. 只读复核已保存记录，不启动仿真（替换为自己的输出路径）：

```bash
bash ros2/twin_axial_navigation/run-nix.sh analyze \
  artifacts/twin_axial_navigation/validation_20261027_final
```

也可以将路径换成某一次 `P0` 子目录。分析不会改写记录。失败退出码非零，请查看 `acceptance.json`、`run_status.json` 和三个进程日志，保留失败目录。

## 场景与控制链路

本轮是垂直平面 S1/F0：区域 `[0,20] × [-20,0]` m，矩形障碍 `[9,10] × [-20,-8]` m，基准起点 `(2,-10)`，终点 `(18,-10)`，无流。

每次生成并保存 `worlds/minimal.world`，其中包含真正加载到 LOTUSim 的静态障碍碰撞盒。规划器从这一份 SDF 读取盒的位置、尺寸并转换到规划坐标。因此地图和 LOTUSim 障碍同源；本阶段没有在线声呐感知或动态地图订阅。

规划坐标 `x = NED y`、`z = 20 − NED z`；Gazebo ENU 为 `(x, 0, z−20)`。故起点对应实际深度 30 m，地图的 z 是带偏置的规划坐标。俯仰正值表示抬头。动力学参数保持 v2 原值，只按工况设置初始位置/姿态。

链路：SDF 障碍 → 原有 A*（0.5 m 网格）→ 原有碰撞检查捷径 → 原有 LOS → 当前 PID / 分配后抗饱和 → 双推进器 → LOTUSim/xdyn → 实时状态反馈。

路径捷径仅提供几何折线，不执行预设时间轨迹。每个 0.05 s 反馈步根据当前真实位置计算 LOS。目标速度上限 0.4 m/s，俯仰指令限制 ±60°。新增任务层在目标附近减速，进入 0.35 m 后锁定制动；到达以实际位置判定。这里没有调用 TerminalApproach，也不声称实现定点悬停。

规划预留净距 1.5 m，以给路径跟踪留余量。执行验收仍使用冻结的 0.9 m 安全阈值（艇体包络半径 0.7 m + 0.2 m 裕度）。xdyn 不模拟艇体与障碍碰撞接触力；安全由记录轨迹与障碍几何独立计算，发生侵入即停止/失败。

## 数值验收标准

| 项目 | 判定 |
|---|---|
| 到达 | 实际位置距目标 ≤0.5 m，连续保持 ≥2 s，300 s 内完成 |
| 避障与边界 | 每两个相邻状态之间的扫掠线段中心净距 ≥0.9 m，不仅检查采样点 |
| 路径误差 | 到有限路径折线的距离，全程 RMS ≤0.35 m、最大 ≤0.8 m，含启动与制动 |
| 饱和 | 双推进器共同缩放系数 α<0.999 的控制步比例 ≤20% |
| 时间与反馈 | 0.05 s 连续推进，反馈序号连续，无控制断流，状态有效且在既有包络内 |
| 分配/抗饱和 | 从真实反馈重算原 PID、抗饱和与分配，核对发布和实际施加的命令 |
| Gazebo 同步 | ≥95% 状态匹配位置 ≤0.01 m、姿态 ≤1° |
| 停止 | 到达后实际推进器归零，进程清理完成 |
| 重复性 | P0 两次共同时间点最大位置差 ≤0.02 m，到达时间差 ≤0.1 s |

安全检查对矩形边界和障碍分别计算；采用当前离散积分步间的线段扫掠近似，不声称证明步内任意连续曲线的安全。

## 保存的证据

- `plan.json`：环境配置、初始条件、原始 A* 路径和执行路径。
- `model.yml` / `worlds/minimal.world`：本次真实模型与场景。
- `transactions.jsonl`：xdyn 全状态、推进器实际输入、时间和看门狗状态。
- `commands.jsonl`：PID、分配、抗饱和与反馈序号。
- `navigation.jsonl`：实际位置、LOS 前视点、进度、目标速度/姿态、到达与安全指标。
- `gazebo_poses.jsonl`：LOTUSim 中的位姿观测。
- `source/`、`flake.lock`、`manifest.json`：代码快照、依赖锁定、记录完整性。
- `acceptance.json` / `suite.json`：单次和套件结果。

本轮只验收一个无流单障碍场景，不等于完成全部场景/洋流实验矩阵。后续先保持同一执行链扩展固定场景和洋流，最后再比较规划方法。
