# Dissertation 模型与系统审查 — 2026-10-25

本轮仅审查和提出配置建议，不修改算法、冻结数据或已有模型。正式要求是非线性、欠驱动 UUV 模型，静态障碍、点到点规划与跟踪，以及水流支持。

## 结论

原 Python 模型已在方程结构上具备非线性、纵向欠驱动和均匀恒流处理。LOTUSim 开环模型具备非线性项及真实外部求解链路，但其纵向三个独立输入为全驱动。缺口主要是两套模型的一致性、具体执行器配置、物理参数依据和 LOTUSim 闭环集成，不是从零重写规划或控制。

## 已核查证据

- `physics/uuv_3dof.py`：姿态相关运动学、刚体及附加质量 Coriolis 项、线性和二次阻尼、正弦恢复力矩；水相对速度及恒定惯性系水流在旋转艇体系下的导数修正。
- `config/vehicles/uuv_3dof_synthetic_v1.yaml`：输入选择矩阵 diag(1,0,1)，禁止直接升沉控制。质量和水动力参数明确标记 synthetic，不能声称为辨识得到的 LRAUV。
- `physics/parameters.py`：检查输入子空间和矩阵性质；目前只接受对角矩阵，需要将非方形执行器分配另设模块，避免直接破坏既有接口。
- `controller/cascaded_pid_3dof.py`：已有 surge/pitch PID、积分限幅和抗饱和逻辑，输出仅 tau_x 与 tau_m。参数 baseline 允许 20 N、8 Nm；不是已经适用于 xdyn 的调参结果。
- `environment/current.py`、`environment/scenario.py`：已有无流及恒流配置。`navigation/navigator.py` 已查询水流并检查执行段安全；这些尚未成为 LOTUSim 实时闭环。
- `ros2/minimal_xdyn/model.py`：线性/二次阻尼和人工 -6 sin(angle) 恢复力矩；独立 surge/fore/aft 三通道；没有当前试验的水流配置。中性浮力由省略净重浮力表达，不是已实现完整重浮力几何模型。
- `ros2/minimal_xdyn/gateway.py`：ROS 命令经网关注入 xdyn 请求，记录原始与实际命令、状态连续性及 watchdog。不能将其描述为未经改造的 LOTUSim 原生命令通路。
- `protocol.py`：NED/FRD 到 ENU/FLU 转换、固定 0.05 s 检查和深度 15–45 m 工作包络。该深度限制不能原样用于旧 x-z 场景；需要统一世界偏移和参考坐标。
- `trial.py`：启动真正 xdyn-for-cs RK4 外部求解器。未在本轮逐项核对锁定 xdyn 内部的 Coriolis/水动力实现，因此不能只凭相似参数宣称它与 Python 方程完全等价。

## 欠驱动的严格区分

旧 Python：纵向状态 (x,z,theta,u,w,q)，直接控制 (X,M)，输入秩为 2，小于三个机械自由度。w 保留为动态变量，并非被设为零。结构上满足纵向欠驱动。

当前 xdyn：X=Ts，Z=Tf+Ta，M=0.5(Ta-Tf)。从三个输入到 (X,Z,M) 的矩阵满秩。在完整六自由度层面仍欠驱动，但在论文关注的纵向平面是全驱动。仅在测试中令 Tf=-Ta 不会改变独立执行器的结构。

当前 xdyn 的 |M| 最大 2 Nm，恢复项为 6 sin(theta)。忽略运动耦合、其他力矩时，静态平衡的俯仰能力仅约 asin(2/6)=19.5 度；这不是瞬态姿态硬上限，但足以说明不能直接复用旧 8 Nm 控制器与急转路径。

## 推荐最终配置：双轴向推进器的合成欠驱动 UUV

保留纵向 x-z 任务；Python 3-DOF 为透明参考方程，LOTUSim/xdyn 为实际执行后端。若继续六自由度积分，论文必须标为“6-DOF 模型的纵向平面实验”，不能称强制约束的 3-DOF；监测出平面状态，不逐步归零。

两台可逆理想推力器均沿 FRD +X，安装于 z=-h（上）与 z=+h（下），质心为原点：

- X=Tu+Tl，Z=0，M=h(Tl-Tu)。
- Tu=(X-M/h)/2，Tl=(X+M/h)/2。
- 候选 h=0.25 m，每台 |T|<=15 N；均为待验证的设计参数，不是商业推进器规格。
- 可实现域 |X|+|M|/h <= 30 N。不能同时要求 30 N 前进力和 7.5 Nm 俯仰力矩。
- 在 X=10 N 时剩余 |M|<=5 Nm。总前进力上限30 N、纯力偶上限7.5 Nm，仅分别成立。

该配置结构性缺少直接升沉输入，能保留现有 X/M 控制结构。它是合成双推进器平台，不是单尾桨/舵面的真实鱼雷型 AUV。展示几何须匹配上下推进器间距，碰撞包络也须同步。

保留原质量、附加质量和阻尼作为第一版数值基线，但必须明确 synthetic，并做参数敏感性与物理合理性说明。20 kg 中性浮力平台的 6 Nm 正弦恢复系数可由约 0.0306 m 的垂直浮心/重心间距解释；这是可选设计解释，并非已验证的原艇几何。若添加真正重浮力模型，须移除重复人工恢复项。

## 必须修改或验证

1. 新建模型版本与两通道协议；从模型层删除直接升沉通道。不要修改旧脉冲基准或冻结配置。
2. 执行器分配按联合可行域处理，记录 requested/allocated/applied，PID 抗饱和使用实际分配结果。
3. 统一仿真时间、状态含义、NED/ENU、FRD/FLU、俯仰正号和旧场景深度偏移。每个场景显式记录原点/偏移。
4. 无流先比较 Python 与 xdyn 的单步和短时响应，再比较有流响应；不能靠相同质量和阻尼就判为同一模型。
5. 将场景水流实际传入外部动力学的相对速度计算。核查附加质量、阻尼及惯性系恒流在艇体系下的旋转处理；禁止仅叠加位置偏移。已有 Python 恒流公式不覆盖任意时空变化流场。
6. ROS 完整状态到已有控制器适配；以反馈仿真时间驱动。gateway 真值反馈不能冒称传感器估计。保持无 MOVE 的动力学闭环。
7. 统一障碍场景和碰撞包络；执行轨迹安全验收可以复用现有几何检查，不必实现碰撞后的接触动力学。可视模型本身不是碰撞模型。
