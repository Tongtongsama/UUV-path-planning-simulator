# Planner v0.6c — 有限范围的 execution-aware 候选路径

日期：2026-09-20。状态：**有限候选实现及首轮 P0/P1 对照已完成**。
结果与限制见 [首轮报告](planner_paired_v1_results.md)。这不是通用执行可行性证明。

目标：零流、固定速度、同一 LOS/Control-v0.5.1/Physics，产生并评估具有更大
转弯空间的候选路径。回答：**保持 guidance/control 不变，改变路径形状与转弯空间，
是否减少实际碰撞和越界？** 不要求建立通用安全认证式执行包络。
依据 [v1 测量](envelope_measurement_results.md) 和 [v2 恢复实验](zero_current_recovery_v2_results.md)。
不修改旧数据、原 LOS 10/16 或原 geometric A*；不同时修复 terminal、current、PID。

## 1. 候选生成：经验改进，不是动力学保证

P0 保留现有 `AStarPlanner` / `AStarConfig`。P1 为可选候选生成器，沿用
`GlobalPlanner.plan(PlanningRequest, PlanningSpace) -> PlanningResult`，输出仍为
Core `Path[Pose]`，不生成控制输入，不导入 Controller/Physics，也不预测完整车辆动力学。

P1 在同一网格与基础 footprint 下，引入非负、可解释的代价或可配置筛选：

- 路径长度及相邻有效线段的 wrapped 转角；连续共线网格步不计作多个角点。
- 障碍物净距与侵蚀边界净距，分别记录；不能把两者混成 `clearance()` 的现有语义。
- 角点间的有效直线长度，以及短间距连续转弯的经验惩罚。
- 已有 initial-heading/startup 合同的预检查；不能通过修改初始姿态规避启动问题。

权重、角度分箱、优选间距、候选数量上限和搜索预算属于独立 P1 配置，
不加入通用 `PlanningConstraints`，在闭环实验前冻结。
若采用 heading-aware A*，搜索状态必须保留到达方向；若后续代价依赖距上一角点的
长度，还需相应状态或多标签，不能将这些历史不同的节点合并为同一个格点。
采用有限间距分箱时应声明近似；不声称连续空间或动力学最优。
可用到 goal region 的欧氏距离作为非负惩罚下的下界启发，不偷偷恢复“精确 goal”语义。

现有 `PlanningSpace.clearance()` 仅表示障碍距离，`bounds` 也只是 bounding box。
首轮限定已有矩形静态场景，由评估适配层提供明确的边界净距；需要通用边界时再引入
扩展能力接口。算法不得读取 Environment 私有容器，或把任意地图 bounding box 当成安全边界。
净距的软代价可采用有记录的离散评估；真正可行性检查仍调用原连续线段验证。

生成顺序与 tie-break 确定，有限候选去重并保留 score 分项。首轮 P1 选择预注册
几何/经验总代价最小的候选，再进行闭环；不能用本次测试场景的闭环成功率反向挑赢家。
首轮实现固定 buffer 的有限 geometric A* 候选，转角与间距仅参与最终排序，
不进入搜索代价。因此不增加方向/间距搜索状态，也不声称该总代价的搜索最优性。
若额外评估其余候选，全部作为探索结果单列，不替换主 P1 结果。
物理闭环失败不能自动触发新的权重搜索或在线重规划。

保持 `vehicle_radius + safety_margin` 原值；偏好更大净距是 P1 的路径选择差异，
不是把全局碰撞判定改宽/改严。经验间距不足与已观察到的不安全分开记录。
过滤后无候选只表示“在当前生成/筛选/预算下未找到”，不能声称物理无解。

## 2. 数据适用域：显式 UNKNOWN，不套用水平表

测量表的来源是水平 cruising 入口、指定速度、零流、固定模型/LOS/PID/限值与记忆。
非水平入段不能仅按相对转角查表，也不能默认旋转整个实验后动力学与执行器余量等价。
实际方向、姿态和 rate、u/w、位置偏差、控制器记忆、current 与配置指纹均属于适用域。
规划时未知的后续入口状态必须保持未知；在完整闭环中用实际状态再次评估。
任务从静止启动也不等同于测量的 cruising 初始条件。

证据查询结果与 `PlanningStatus.SUCCESS` 分开；可用独立 CandidateAssessment
记录逐角点结果、原因和来源，不把 UNKNOWN 塞成正常规划失败或静默变成支持。

| 证据状态 | 含义与首轮处理 |
| --- | --- |
| SUPPORTED | 声明入口/控制域匹配，完整恢复及所需扫掠 corridor 有证据；仅表示该声明范围内的经验支持 |
| UNKNOWN | 删失、缺样、非水平入口、状态/记忆未知或配置不匹配；保留原因，允许探索但不声称安全 |
| UNSAFE_OBSERVED | 同一声明条件/corridor 下已观察到实际违规；拒绝对应候选局部连接，不扩大为所有状态都不可行 |

首轮允许 UNKNOWN 候选进入受控仿真，并统一附加预注册的有限惩罚；
不能因缺水平入段证据就默认全拒绝，也不能把该惩罚称为已校准的风险概率。
若以后研究保守拒绝 UNKNOWN，须独立实验，并报告拒绝率与机会损失。
不得对未测速度/转角/入口状态静默插值、取最近表项或给空值补零。

24 个 v2 持续恢复条件不是现成的 SUPPORTED 表：仍缺实际入口与具体 corridor 匹配。
使用恢复距离时区分 first recovery、last reentry、reexit 和观察窗末保持；
首次恢复后再次出带，不能使用更短的第一次距离。右删失不是有限上界。
首轮优选角点间距可以作为经验设计值，即使不能由表证明，也必须标成 heuristic，
不能把静态评分“间距达标”误称为实际转弯恢复。
0.35 rad/s 只保留诊断；不作为 Planner 硬拒绝阈值。

## 3. 完整路径验证：真实初始状态，连续闭环

候选先验证起终点、goal tolerance、长度约束和全部连续线段碰撞/边界。
实际执行的 processed path 必须再次验证并记录 hash。为避免后处理抹掉 P1 的
角点设计，首轮两臂均仅允许去重与同向共线冗余点消除；180° 折返必须保留。
简化后重新验证；禁用 shortcut 和平滑。
这属于新实验共同条件，不是直接复跑旧 0.5 m/s baseline。

从同一个真实初始 VehicleState 开始，沿用同一 startup、LOS、内环/前馈、限幅、
anti-windup、Physics、capture 和安全判定。控制器在任务开始时正常初始化一次，
角点处不重置状态、速度、姿态、积分或物理时钟；不拼接孤立转弯轨迹证明整条路可执行。
Planner 不调用控制器；实验 runner/Navigator 负责闭环和证据记录。

前视点可能先于切段启动转向：另记录前视弧长首次触及角点时的施令前状态与积分记忆，
并记录首次偏离入段切向命令和实际切段状态；切段状态不等于测量入口。
未匹配测量入口/状态/记忆/corridor 的结果保持 UNKNOWN。
在每个实际切段处记录状态、记忆、相邻角点间距、是否已恢复、
下一角点是否在恢复前到来、实际扫掠、reference/actual 偏差及首次安全违规阶段。
连续多转弯造成的相互干扰必须作为完整任务结果，不能只引用单角点支持标志。
用于离线诊断的“进入末段区域”定义须在 runner 配置中冻结，两臂相同；
不得据此新增 TERMINAL_APPROACH 生产阶段或改变已有 capture 交接。

失败保留完整结构化结果：规划拒绝、startup、PATH_FOLLOWING 碰撞/越界/停滞、
terminal/capture、超时和数值异常分别分类。终端未修复不阻塞路径执行效果研究，
但不能掩盖最终任务失败；不放宽终点条件或增加某一臂的预算获得成功。

## 4. 公平比较与验收

首轮定义独立的 **P0/P1 zero-current 0.2 m/s exploration**：两臂同为 0.2 m/s，
guidance 都使用冻结 LOS，唯一方法差异是候选路径生成/选择。
它不与旧 0.5 m/s 的 10/16 直接比较，也不是 timed 与 LOS 的再次对照。

共同冻结初始状态、零流静态场景清单、网格分辨率、goal region、footprint、
后处理规则、控制/Physics/启动/捕获参数、有效限值、dt、预算和终止条件。
场景从已有静态零流场景中选定，必须包含开放 sanity case 和障碍/多转弯场景；
不得看结果后剔除失败场景。若将原含流场景改为零流，须作为新 fixture 标识。
每场景每臂至少两次；输入/源码/参数指纹和每次独立结果全部保留。
两臂搜索操作可能不同，分别报告候选数、扩展节点与耗时，不能隐藏 P1 的额外计算。
规划失败计入总分母；不得只对两臂都成功执行的路径汇总收益。

主要比较 PATH_FOLLOWING 的：碰撞/越界、进入预定义末段诊断区域、最小实际障碍净距
与边界裕量、finite-polyline 最大/RMS 偏差、UNKNOWN/不支持连接数量、
下一转弯前未恢复事件、饱和与 q 诊断。每臂偏差相对其自己的参考路径，
不能仅凭该误差下降推断路径更安全；同时报告长度、总物理时间和安全结果。
失败路径的较短观测窗标明删失；不将少走路导致的低累计代价解释为性能改善。
最终 SUCCESS 仍报告，terminal 失败另列，不由 PATH_FOLLOWING 改善代替。

实现验收需证明：P0 保留、P1 能生成不同的更大转弯空间候选、几何连续验证有效、
UNKNOWN 不被静默支持、配置/实际入口不匹配可诊断、闭环无角点重置、
两臂共同条件一致且重复可复现；新增及已有测试通过，并交付失败记录和 manifest。
研究结论允许“没有改善”或权衡，不能要求所有场景成功来宣布工具完成。
本规范不承诺 P1 必定减少碰撞，也不以通过全部复杂场景为 ROS 2 adapter 的先决条件。
完成这一有限对照后按证据决定下一步；Terminal 修复、current-aware planning、
PID/新 guidance 均保持独立工作项，ROS 2 仍为第一扩展目标。
