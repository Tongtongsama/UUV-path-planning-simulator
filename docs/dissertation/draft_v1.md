## 摘要

欠驱动水下无人航行器（UUV）的点到点导航能力，取决于规划、引导、控制与执行器分配四层能否在同一个动力学闭环中自洽工作。已有研究多将高层规划与低层控制分置于不同框架验证，导致"几何可行的路径"与"动力学可执行的轨迹"之间缺少可检验的衔接；同时，执行器饱和与海流扰动常被单独处理，二者对闭环的共同作用缺少系统性证据。本文面向纵向 x–z 平面，构建并验证了一套基于 LOTUSim 的欠驱动 UUV 点到点导航仿真系统。

系统采用合成中性浮力 UUV 模型：两个上下分置、量程 ±15 N 的可逆轴向推进器，配置矩阵秩为 2，缺少直接升沉通道，欠驱动由此而来；参考方程取纵向三自由度（`x, z, θ, u, w, q`），实际积分由 LOTUSim/xdyn 的六自由度后端完成。方法链为：八邻域 A* 在已知静态栅格上生成全局路径（障碍按 0.70 m 艇体半径加 0.20 m 安全裕度膨胀）；有限段进度投影 LOS（前视 2.3 m）给出俯仰与速度指令；级联 PID（位置→速度、深度→俯仰修正，PI + 俯仰角速率反馈）输出广义力；双推进器按 `|X|+4|M|≤30` 分配并做方向保持的统一缩放。

验证按模型、控制、导航、复现四级展开。模型级 M1–M7 全部通过：零输入静止 30 s 漂移小于 1e-4；零状态瞬时加速度 `u̇` 相对误差 0.40%、`q̇` 0.77%；固定输入 20 s 的步长减半终点差 2.73e-10 m；1880 个既有状态的坐标往返误差为 0。导航级在 3 场景 × 3 水流 × 5 初态（P0–P4）加 9 次 P0 重复共 54 条上，Python 参考后端全部动态通过且记录可重放；真实 LOTUSim/GUI 后端 54 条中 53 条通过，45 条名义条目 44/45，九组"每组至少 4/5 且 P0 必须通过"的统计口径全部满足。边界实验给出明确适用域：向上恒流 0.10 m/s 时虽安全到达但 RMS 0.419 m、最大误差 0.962 m 超限；0.15 与 0.20 m/s 分别在 78.0 s、72.4 s 触发净距违规；阻尼系数整体乘 0.8 与 1.2 两种极端参数下 Python 与真实后端均通过。

结论是：在"已知静态地图、均匀恒流、真值状态反馈、推力受限"这一明确假设集内，四层链路可复现地完成名义导航任务，并存在可量化、可复现的失效边界；但该结果不构成对真实海况、感知闭环或任意未知流的验证。

**关键词**：欠驱动 UUV；点到点导航；LOS 引导；级联 PID；控制分配；LOTUSim；仿真验证

## 1 引言

### 1.1 背景

UUV 的价值在于长航程、近海底、测绘级定线的作业能力[1][3]。这类作业对自主性的最低要求，是从起点安全抵达目标点：既不能碰障碍，也不能在扰动下持续偏离计划航线。工程上，这一能力被拆成规划、引导、控制与执行器分配四层，分别对应不同的时间尺度与假设。

近三十年，四层各自都相当成熟：全局规划在已知静态图上已能给出可证明最优的栅格路径[17][19]；LOS 引导把横向误差映射为期望航向，并已从直线、无流推广到曲线与常值流[27][28][29]；PID 及其级联形式是小型 AUV 的实际标准[30][31]；控制分配与抗饱和则在过驱动平台上形成了完整理论[11][12][13]。

### 1.2 问题与矛盾

问题不在单层，而在层与层之间。

第一，几何可行与动力学可行不是一回事。运动动力学规划早已指出，在相空间中受速度/加速度界约束的可执行轨迹，其几何投影可能根本不是最短路径[32]；而工程上普遍采用的分层架构，恰恰把高层规划与低层避障/跟踪切开[33]，两层之间没有转弯半径、减速距离这类可行性契约。

第二，欠驱动使上述缺口更硬。欠驱动载具的可跟踪轨迹集合小于全驱动载具，任意光滑参考并不可跟踪[8]；而多数规划器输出的折线路径在拐点处曲率不连续，直接交给跟踪层会在拐角处要求执行器瞬时改变力矩[24]。

第三，执行器饱和与海流常被分别处理。饱和的正确位置是分配层——判断期望广义力是否落在可达集内，而不是对推进器逐通道限幅[11]；抗饱和则被设计为"只在饱和时介入"的事后补偿[13]。但当二者与欠驱动、与恒流同时出现时，饱和是"推力不够"还是"跟踪误差累积"，并不总能从指标上区分。本文的边界实验正是为了把这两者分开。

第四，验证层级容易混淆。仿真模型的验证（verification）与确认（validation）是两件事，且仿真器本身不提供物理真实性[41][42]；平台自带的水动力/环境模型是否被启用、被验证，必须在论文里显式交代。

### 1.3 本文工作

针对上述缺口，本文的工作是"建一条完整链路并把它验到边界"，而不是提出新算法：

1. **模型与执行器**：给出合成 UUV 的纵向参考方程、双推进器配置矩阵与分配律，明确"欠驱动 = 缺少直接升沉通道"而非"控制器不用某个执行器"，并用 M1–M3 把分配、静态、瞬时响应逐项核到数值。
2. **分层方法链**：A*（栅格、膨胀 0.9 m）→ 有限段进度投影 LOS（前视 2.3 m、角点降速 0.12 m/s）→ 级联 PID（含条件积分抗饱和）→ 分配（`|X|+4|M|≤30`，方向保持缩放），并给出每一层的输入输出契约与失效判据。
3. **可复现的验证协议**：3 场景 × 3 水流 × 5 初态 + 9 重复 = 54 条的固定矩阵，配 M1–M7、C1–C3、N1–N6、R1–R2 四级阈值，全部冻结源码与配置哈希。
4. **边界与失效证据**：给出恒流 0.10/0.15/0.20 m/s 与阻尼 ±20% 的分后端结果，明确"饱和比例 0 却仍然失败"这一事实，从而把失效归因于跟踪能力而非推力饱和。

## 2 相关工作

### 2.1 建模、降维与欠驱动

海洋载具的通用模型是六自由度矢量形式，海流只能通过相对速度进入阻尼与科氏项[4]。工程上为降低复杂度，常按任务提取纵向平面子系统。Healey 与 Lienard 在完整六自由度模型上设计覆盖操舵、下潜与速度的滑模自动驾驶仪，但其有效性建立在"设计时假定解耦建模"之上[6]——这是解耦作为**假设**而非事实的原始出处。

欠驱动的严格含义是控制输入维数小于自由度维数[5]。文献[5]用"全驱动/冗余/不可驱动"的配置语言描述推进器布局；本文把同一事实写成配置矩阵秩判据 `rank(B)<6`，属于等价的代数化改写，引用时作了区分。

降维的代价必须交代。文献[10]在垂直面深度控制中采用小纵倾线性化，而文献[48]明确指出"小纵倾是相当强的限制条件，可能给动力学带来严重建模误差"（原文：*This is a quite strong restricting condition in underwater operations and may cause serious modeling inaccuracies*）。本文因此把"小姿态角"列为显式假设，并用姿态包络（参考 70°、实际 75°）作为其可检验边界。

### 2.2 全局规划与路径处理

A* 以 `f=g+h` 的启发式最佳优先搜索给出最小代价路径，其最优性来自启发函数的可采纳性，而非算法名称本身[19]；放松可采纳性可换速度，代价是变为有界次优[19][20]。需要注意，A* 的"最优"是图上的最优，栅格离散化已经把连续问题近似掉了[17]。

栅格与障碍膨胀决定了"安全"能否被保证。占据栅格是带不确定性的随机场[21]；把障碍按艇体外形做 Minkowski 膨胀后，"点机器人避障"才等价于原问题[22][17]。但在栅格近似下，这一等价退化为分辨率意义下的近似，安全距离因此是**设计参数**而非物理保证。

路径后处理方面，捷径化以"无碰"为前置条件反复用更短子路径替换[23]——原文明确写了 `collision-free` 这一条件；连续曲率路径（CC 路径）由直线段、圆弧与回旋曲线构成，作者自认"在长度上并非最优"[24]。本文因此不做捷径化与平滑，只保留去重与共线点消除，以避免把"几何更顺"误当成"更可执行"。

### 2.3 引导与控制

LOS 的几何是：以路径切向、横漂误差与前视距离共同决定期望航向，收敛速率近似为速度与前视距离之比。原始文献中还有两个常被忽略的环节——**投影算法**（把载具投影到路径上求横漂）与**参考模型**（平滑航路点切换并向控制器提供期望航向的导数），后者用于避免切换时航向阶跃[27]。

积分 LOS 以附加积分状态消除常值外扰引起的稳态误差，原文明确定位于直线路径跟踪[28]；其级联稳定性结论针对"引导 + 航向"结构，不含速度通道与执行器饱和[28]。自适应版本进一步把未知常值流转化为可估参数，但适用范围明确限定为**水平面运动**[29]。本文的纵向 x–z 平面恰在其外，这一点在讨论中作为边界保留。

PID 类控制器仍是小型 AUV 的工程标准[30][31]。其代价是增益与工况强绑定、缺乏对约束的前瞻处理；无模型 iPID 以超局部模型替代水动力模型，但其中 `α` 是非物理常数，"无模型"不等于"无参数"[31]。

### 2.4 执行器饱和、分配与海流

饱和的本质是指令落在可达集之外。此时对推进器逐通道限幅会改变合力方向，正确做法是在分配层统一处理约束与优先级，必要时把期望力投影到可达集边界[11][12]。抗饱和则是"先设计标称控制器、再补一个只在饱和时介入的补偿器"[13]；工程上更常见的是条件积分[14]，而 AUV 上的实测证据表明双环结构配抗饱和可显著降低超调与调节时间[14]。

海流建模以"恒定、无旋、空间均匀"为前提[4]，因此以恒流为唯一扰动源的实验只能验证系统对**常值偏置**的抑制能力，不能外推为对真实时空变化流的适应性。现有抗流引导多假设流已知或可估[15][16]，与"给定恒流真值"的验证路线目标不同。

### 2.5 仿真与验证

通用机器人仿真器提供积分、传感器模型与接口抽象的骨架，其原生模型不含水动力[38]。海洋多域仿真平台（如 LOTUSim）补齐了水下环境，并自带受 Ekman 启发的分层海流模型[39]；但平台能力不等于模型已被验证，仿真结果的物理可信度仍取决于用户实现的模型与验证过程[41][42]。

可复现性方面，"任何手工操作环节都是不可复现性的来源"，配置、命令、随机种子与依赖版本必须冻结[43]；记录与重放机制（如 ROS 的时间戳消息记录）只提供工程手段，不提供硬实时保证[40]。

## 3 问题描述与建模

### 3.1 坐标系与状态

规划平面使用世界坐标 `(x_p, z_p)`，`x` 向前（东）、`z` 向上，单位为米；三维展示时映射到 Gazebo ENU 的 `(x_p, 0, z_p-20)`。艇体系采用 FRD：`x` 前、`y` 右、`z` 下；`q`、`θ` 抬头为正。纵向状态取 `(x, z, θ, u, w, q)`，其中 `w` 沿艇体下方为正并保持为动态变量。

运动学取

```
ẋ = u cosθ + w sinθ
ż = u sinθ − w cosθ
θ̇ = q
```

该式与真实的"上升/下降"试验方向一致；文献中曾出现的 `ż = u sinθ + w cosθ` 变体被明确拒绝（否则上升与下降的符号会反）。

### 3.2 纵向参考方程与参数

参考方程保留刚体/附加质量耦合、二次阻尼、姿态运动学与正弦恢复项：

```
(m + m_a) u̇ = f_u(u, w, q) + X + d_u
(m + m_a) q̇ = f_q(u, w, q) + M − 6 sinθ + d_q
(m + m_a) ẇ = f_w(u, w, q) + 0 · Z + d_w
```

其中 `X` 为轴向合力、`M` 为俯仰力矩，`Z ≡ 0`（无直接升沉通道）。参数取合成有效值：

| 项目 | 取值 |
|---|---|
| 刚体惯量 | `diag(20 kg, 20 kg, 8 kg·m²)` |
| 附加质量 | `diag(5 kg, 8 kg, 2 kg·m²)` |
| 线性阻尼 | `diag(4, 6, 3)`，平移 N/(m/s)、转动 Nm/(rad/s) |
| 二次阻尼 | `diag(1, 1.5, 0.5)` |
| 俯仰恢复 | `−6 sinθ` Nm |
| 积分 | RK4，`dt = 0.05 s`（验证用 0.025/0.0125 s） |

这些是**合成有效参数**，用于可解释的仿真研究，不是辨识值，也不能由外形推导。6 Nm 的恢复系数可解释为 20 kg 中性浮力载具约 30.6 mm 的浮心—重心间距的等效作用，但本模型只计一次恢复项，不再叠加完整静水恢复力，以免重复计力。

### 3.3 执行器配置与欠驱动

两个可逆轴向推进器位于 `(0,0,∓0.25)` m，均沿 `+X`，输入 `T_u, T_l ∈ [−15, 15]` N：

```
X = T_u + T_l
Z = 0
M = 0.25 (T_l − T_u)
```

配置矩阵（行 `X, Z, M`）为 `[[1,1],[0,0],[−0.25,0.25]]`，秩 2。欠驱动来自**缺少直接升沉通道**，而不是控制器主动弃用某个已有执行器。分配律与可行域为

```
T_u = (X − 4M)/2,   T_l = (X + 4M)/2,   |X| + 4|M| ≤ 30
```

即纯前进极限 30 N、纯力偶极限 7.5 Nm，二者不可同时取得。v1 采用方向保持的统一缩放：先求未限幅 `T_u, T_l`，再令 `α = min(1, 15/max(|T_u|,|T_l|))`，两路同乘 `α`；请求值、分配值、实际施加值与 `α` 全部记录，抗饱和使用**实际**广义力而非限幅前的请求值。

### 3.4 海流

海流在惯性系给定，仅以相对速度影响水动力，不直接平移轨迹：流向在规划世界坐标为 `(v_x, v_z)`，艇体系分量随姿态变化，禁止把艇体系分量也当作常量。本文使用三档：`F0=(0,0)`、`F1=(−0.05,0)`、`F2=(0,+0.05)` m/s，作为同一场景内唯一的环境自变量；三种流不分别调参。

### 3.5 假设与边界

本文结论在以下假设集内成立，逐条可检验：

1. 已知静态地图、矩形障碍、无动态障碍；
2. 均匀恒流，无风、浪、剪切与垂向分层；
3. 真值状态反馈，不含感知、估计与延迟；
4. 参考俯仰限幅 70°，实际 `|θ|>75°` 判包络失败；
5. 无推进器动态（无 RPM、死区、滞后），限幅为 ±15 N。

第 2 条与文献[4]的三条前提（恒定、无旋、空间均匀）一一对应；平台的 LOTUSim 自带分层流能力[39]，本文**未启用**，这是有意的取舍而非能力缺失。

## 4 方法

### 4.1 全局规划

在 `20 m × 20 m` 的规划域 `[0,20]×[−20,0]` 上，把静态障碍栅格化，按 `r = r_vehicle + r_margin = 0.70 + 0.20 = 0.90 m` 膨胀，八邻域 A* 搜索最小代价路径，启发函数取到目标的欧氏距离（非负、可采纳）。路径后处理**只做**相邻重复点去重与同向共线点消除；**不做**捷径化与平滑——原因是捷径化会把路径推近障碍[23]，而连续曲率平滑会改变拐角几何[24][25]，两者都会使"规划结果"与"被检验的执行结果"不再是同一条线。

三个场景的障碍矩形（规划平面米）为：

| 场景 | 障碍范围 (x, z) | 用途 |
|---|---|---|
| S1 | `[9,10]×[−20,−8]` | 单挡板，简单绕障 |
| S2 | `[6,7]×[−20,−7]`、`[13,14]×[−13,0]` | 双挡板，需换向 |
| S3 | `[6,7]×[−20,−5.5]`、`[13,14]×[−14.5,0]` | 双挡板收紧，上下转向空间最小 |

起终点固定为 `(2,−10)` 与 `(18,−10)`，初始水平静止；五个初态 P0–P4 在 P0 基础上加 `±0.10 m` 位置与 `±3°` 俯仰扰动。规划器在初态改变时允许重新规划，但种子固定为 0。

### 4.2 LOS 引导

引导采用有限段进度投影 LOS。设当前活动段 `P_i → P_{i+1}`，切向 `t=(cosα, sinα)`、法向 `n=(−sinα, cosα)`，投影点 `P_proj = P_i + μ(P_{i+1}−P_i)`，`μ=clip(λ_raw,0,1)`，则

```
横漂误差  e = n · (P − P_proj)
期望俯仰  θ_cmd = α − atan2(e, Δ)
```

`Δ = 2.3 m` 为固定前视距离。切段由端点门控完成：门 `i` 在"到 `P_{i+1}` 的距离 ≤ `r_i`"或"`λ_raw ≥ 1` 且 `|e| ≤ r_i`"时打开，其中 `r_i = min(r_switch, 0.45 L_i, 0.45 L_{i+1})`。这一"管道条件"防止载具在远离路径时仅因穿过无限延长面而提前切段；进度 `committed_s` 单调不减，单步推进量受实际位移加松弛量约束。

速度剖面为分段常数：巡航 0.48 m/s，角点附近 0.12 m/s，速度参考变化率 0.04 m/s²，俯仰参考变化率 0.12 rad/s。LOS 只输出俯仰与速度参考，**不直接产生力矩**——这是"引导"与"控制"的分界。

原文中的参考模型一环[27]在这里由速率限幅承担：若不限幅，航路点切换处的航向阶跃会直接打到内环。

### 4.3 级联 PID 与抗饱和

控制器输入为当前状态与选定的参考状态，输出广义力 `(τ_x, τ_m)`，其余分量为零。设世界位置误差 `e_x^n = x_d − x`、`e_z^n = z_d − z`，投影到当前艇体前向：

```
e_xb = cosθ · e_x^n + sinθ · e_z^n
u_c  = clip(u_d + k_x e_xb, −u_max, u_max),   e_u = u_c − u
```

深度偏差转成俯仰修正，方向随航行方向翻转（`s_u = +1` 当 `u_c ≥ 0`，否则 `−1`）：

```
Δθ_c = clip(s_u k_z e_z^n, ±Δθ_max)
θ_c  = θ_d + Δθ_c
e_θ  = wrap[−π,π)(θ_c − θ),   e_q = q_d − q
```

输出

```
τ_x,raw = K_pu e_u + K_iu I_u
τ_m,raw = K_pθ e_θ + K_iθ I_θ + K_dq e_q
τ_x = clip(τ_x,raw, ±τ_x,max),   τ_m = clip(τ_m,raw, ±τ_m,max)
```

抗饱和采用**条件积分**：候选积分 `I_c = clip(I + e·dt, ±I_max)` 仅当对应原始输出未饱和，或当前误差会把已饱和输出拉回可行域时才被接受，否则保持上一步积分。这是"广义力限幅"，不是执行器分配；推进器几何与动态由 4.4 的分配器处理。

需要强调：`k_z` 外环是**有界启发式**——参考俯仰由深度误差线性映射而来，不是 Lyapunov 设计，其稳定性论证不在本文范围。

### 4.4 任务流程与判定

单次任务的顺序为：规划一次 → 用初始状态时间生成参考 → 控制器复位 → 在每个控制步采样参考、计算指令、限幅、按**实际位姿**查询海流、RK4 积分一步 → 校验状态有效性 → 检查"本步实际位移弦"与障碍/边界的安全距离。安全判定优先于成功判定，成功优先于超时。

到达条件为：位置误差 ≤ 0.50 m、速度模 ≤ 目标速度容差、`|q|` ≤ 俯仰角速率容差，三者连续保持 2 s。超时为每次任务 300 s 仿真时间。饱和统计以"实际施加的控制量触及限幅"为准，按控制步计比例，名义要求 ≤ 20%。

## 5 仿真平台与实现

### 5.1 双层后端

系统保留两条后端，用途不同：

- **Python 参考后端**：按 3.2 的纵向方程与 RK4 积分，用于模型级验证、控制阶跃与全矩阵的快速复算。它是"参考方程"，不是真实载具。
- **LOTUSim/xdyn 后端**：六自由度积分，纵向工况通过配置约束在 `y`、`roll`、`yaw` 的小偏差内（`|y|≤0.05 m`、`|roll|≤2°`、航向偏差 ≤2°），超限判平面假设失效，不做投影或归零。它承担"真实闭环"的角色，但仍是仿真器而非实艇。

两后端的配对检查在固定输入 20 s 内进行，要求逐时刻位置差 ≤ 0.05 m、俯仰 ≤ 1°、`u/w` 差 ≤ 0.02 m/s；无流与两个恒流分别检查。不合格时先查方程，不以调 PID 掩盖。

### 5.2 集成与记录

仿真侧经 ROS 2 桥接发布位姿与订阅控制；Gazebo 负责可视化。每个控制步记录：请求指令、分配后指令、实际施加力/力矩、`α`、参考状态、实际状态、本步扫掠净距、饱和标志。每份运行记录可离线重放：按记录的初始状态重算 RK4 步、引导、PID/抗饱和与分配，并重算净距与到达判定。

### 5.3 冻结与可复现

正式矩阵使用单一源码快照（114 个源文件，聚合 SHA256 `a44047…5a11d9`），每条运行生成 `preregistration.json`、依赖版本与 `manifest`；运行前后逐文件比对现场源码与快照。字符层面的复现约定沿用文献[43]的四条：结果可追溯、避免手工步骤、归档依赖版本、脚本纳入版本控制；记录—重放机制本身只提供工程手段，不保证实时性[40]。

## 7 结果

### 7.1 模型级（M1–M7）

分配与欠驱动：静态矩阵秩为 2，`Z` 输入恒为 0，单台推力超限容差与 `X`/`M` 重构误差均在 1e-9 内。静止：无流水平静止 30 s（600 步），位置与姿态漂移均小于 1e-4。瞬时响应：`T_u=T_l=1 N` 时首有效步测得 `u̇ ≈ 0.07968 m/s²`，相对 0.08 差 0.40%；`T_u=−1, T_l=1 N` 时 `q̇ ≈ 0.04961 rad/s²`，相对 0.05 差 0.77%——这是 `dt=0.05 s` 的有限差分，不是求解器的瞬时导数输出，论文按此口径表述。能量：撤力后 10 s 的机械能（含恢复势能）与初始值之比为 0.0383，未增加。步长收敛：0.05 与 0.025 s 的 20 s 终点差为 2.73e-10 m、1.89e-7°、1.91e-10 m/s，继续减半不增。坐标与时间：对 1880 个既有有效状态做往返变换，位置误差 0、旋转矩阵最大元素差 4.53e-16、`dt` 误差 7.08e-16 s。

| 工况 | 后端 | 结果 | 到达 (s) | 最小净距 (m) | RMS (m) | 最大误差 (m) |

三点值得强调：

1. **0.10 m/s 是"安全但超差"**：它安全到达，却在 RMS 与最大误差上双双越界。这说明"没撞"与"跟上"是两个独立判据，不能互相替代。
2. **0.15/0.20 m/s 先在跟踪上失守，再在净距上违规**：两次违规分别发生在 78.00 s 与 72.40 s、第二道障碍之前，且**饱和比例均为 0**、姿态与速度包络仍通过。因此证据支持的结论是"当前引导/控制在上述流速下的**跟踪能力**不足"，而不是"推进器饱和"或"姿态失控"。
3. **阻尼 ±20% 的两端都通过，但 D120 的真实 RMS 为 0.3443 m，距 0.35 m 阈值只剩 5.7 mm**。这既说明系统对该参数不敏感，也说明它并不宽裕。

三档强流只有 Python 失败证据，真实后端按"Python 先决"门禁**拒绝启动**，因此不能称为"真实 xdyn 在强流下失败"，更不能称为"真实强流试验已完成"。

## 8 讨论

### 8.1 回答三个研究问题

**RQ1（模型能否建立并验证）**：能，但限于纵向任务与合成参数。M1–M7 覆盖了分配、静止、瞬时响应、能量、步长收敛、双后端配对与坐标时间一致性；不能外推为"任意六自由度"或"真实艇型精度"。

**RQ2（环境—规划—控制能否集成完成导航）**：能，且可复现。54 条 Python 全通过、9 组重复性为零差异、真实后端 44/45 名义通过，说明"规划地图与仿真环境一致、状态驱动控制、运动由积分产生"这三件事在本配置下成立。

**RQ3（水流与执行器限制如何影响性能）**：影响是**非单调且分层**的。0.05 m/s 通过、0.10 m/s 安全但超差、0.15 m/s 起出现净距违规；而饱和比例在三档强流下都是 0。也就是说，限制首先表现为**跟踪能力**，其次才表现为**几何安全**，而"推力饱和"并不是这条链上的第一块短板。

### 8.2 与文献的关系

- 本文的降维与解耦沿用[6]的假设，但把"小姿态角"变成可检验的包络（70°/75°），并把"解耦是假设"写成显式声明；
- LOS 实现遵循[27]的几何，并补上了投影与门控；与[28]的积分 LOS 相比，本文**未**加积分项，抗流由内环积分承担，代价是难以把"控制误差"与"积分饱和"分开；
- 与[11][13]相比，本文把饱和处理放在分配层（可达域约束）与控制器层（条件积分）两处，并在结果中单列饱和比例，使"是否饱和"成为可检验量而非实现细节；
- 与[39]相比，本文只用了平台的恒流档，未启用其分层流能力；这是研究问题限定，也是明确的局限。

### 8.3 局限

1. **无实艇、无感知**：全部结果为仿真、真值状态；不构成 sim-to-real 证据[46][47]。
2. **海流是常值**：仅在单一常值偏置意义上验证，未覆盖时空变化流；文献[4]的三条前提中，"空间均匀"连实测单点数据都无法验证。
3. **未做捷径化与平滑**：路径保留折角，因此结果不覆盖"平滑后 clearance 下降"这一已知风险[23][24]。
4. **强流真实未执行**：Python 先决门禁拒绝启动，属明确未完成项。
5. **一次失败未归因**：S1/F1/P4 的反馈停滞与清理失败根因未证实。
6. **阈值贴近**：S3/F2 的 RMS 与 D120 的 RMS 都已接近上限，说明"通过"不等于"裕度充足"。

## 9 结论

本文构建并验证了一套面向纵向平面、欠驱动、带执行器饱和与恒流扰动的 UUV 点到点导航仿真系统。系统把 A* 全局规划、有限段进度投影 LOS、级联 PID 与双推进器分配串成一条可复现的链路，并用四级验证协议（模型 M1–M7、控制 C1–C3、导航 N1–N6、复现 R1–R2）在 54 条固定矩阵上完成评价。

主要结论有三点。其一，在"已知静态图、均匀恒流、真值反馈、±15 N 推力"的假设集内，四层链路可复现地完成名义导航：Python 参考 54/54，真实后端 44/45 名义条目，9 组重复性零差异。其二，失效边界是可量化的：向上恒流 0.10 m/s 时安全但跟踪超差，0.15 m/s 起出现净距违规，而三档强流的饱和比例均为 0——瓶颈在跟踪能力而非推力饱和。其三，降维与解耦的代价必须显式声明：小纵倾是强假设，LOS 的抗流结论在文献中限于水平面，而本文的纵向平面恰在其外。

后续工作有三条优先级：补齐真实强流试验与 S1/F1/P4 的根因分析；把恒流扩展到平台已支持的分层流；以及在引入路径平滑时同步建立 clearance 重检，使"更顺的路径"仍然可被安全判据检验。
