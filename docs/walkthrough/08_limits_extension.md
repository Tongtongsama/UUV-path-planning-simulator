范围：已建立的能力边界、6-DOF 迁移的接口冲击、RRT*/MPC/RL 的插入点、论文待补项、方法论可迁移性。

## 1. 通俗版

### 1.1 一句话说清边界

**做到了**：一条可复现、可审计的**仿真内**闭环——规划 → 制导 → 控制 → 6-DOF 动力学 → 场景回写 → 门禁 → 证据矩阵。

**没做到**：
- 真实艇（无参数辨识、无硬件在环）；
- 真实海况（平坦海底、无波浪、无垂直剪切）；
- 操作认证（simulator-only）；
- 干净环境一键复现（缺可移植发布包）。

这不是"差一点"，而是**四种不同性质的缺口**：缺标定、缺环境模型、缺认证流程、缺工程打包。

### 1.2 6-DOF 迁移：为什么不能"允许大数组"

最诱人的错误做法是：把 `Pose`/`Twist` 从 6 维放开到"随便填"，让 `y/roll/yaw` 也能非零。这样能跑，但会破坏三件事：

1. **子空间断言失效**：`extract_reduced_state` 的 `1e-12` 检查变成摆设，静默错误重新回来；
2. **积分器接口含糊**：`Integrator.step` 现在假设 `shape=(6,)`，6-DOF 需要 `(12,)` 或一个新类型；
3. **安全性判定含糊**：`segment_clearance` 是二维的，三维要重新定义"扫掠体"。

所以 README 列的是一份**协调迁移清单**（12 项），核心意思是：Core 可以不变，但要**新增**而不是**放宽**。

| # | 工作 | 冲击哪个模块 |
|---|---|---|
| 1 | 完整 12 维状态映射 + 欧拉角奇异策略（或四元数内部表示） | Core / Physics |
| 2 | 审计过的 ENU/SNAME 6-DOF 运动学与双向变换 | Physics |
| 3 | 完整 6×6 刚体惯量 + 附加质量（含质心/浮心偏置、惯性积） | Physics 参数 |
| 4 | 独立推导的刚体与附加质量科氏矩阵（斜对称 + 能量检验） | Physics |
| 5 | 用重量/浮力/质心/浮心替代集总恢复系数 | Physics 参数 |
| 6 | 三维流场 + 角速度流假设 + 对应的 `ν̇_c` | Physics / Environment |
| 7 | 6-DOF 阻尼与横流/升力模型（显式符号与参数来源） | Physics |
| 8 | 独立的执行器/推进器/舵模型 + 分配矩阵 | Controller → 新增 Allocation |
| 9 | 三维边界、障碍几何、艇体外形、碰撞查询 | Environment |
| 10 | 维度感知的 derivative/integrator 抽象（或并行 6-DOF 类型） | Physics |
| 11 | 带单位/坐标系/来源 commit/转换/置信度的参数配置 | Config |
| 12 | 极限工况、守恒/无源性、收敛性、敏感性、与独立模型对比 | Validation |

**其中 8、9 是真正的架构变更**（新增一层），其余是替换实现。

### 1.3 RRT / MPC / RL 该插在哪

架构已经留好了插槽，关键是"插在协议后面"而不是"插在流程中间"。

| 想加的东西 | 插槽 | 需要做什么 | 不需要动什么 |
|---|---|---|---|
| **RRT\*** | `GlobalPlanner.plan()` | 新类实现同一协议；返回 `PlanningResult` | Navigation、Controller、Physics 全不动 |
| **MPC** | `Controller3DOF.step()` | 新类返回 `ControlInput`；`reset()` 清空内部状态 | Planner、Physics、Environment 不动 |
| **RL 制导** | `LOSNavigationAdapter` 同层 | 输出 `BodyGuidance3DOF`，仍需满足 `GuidanceController3DOF` | 控制器、动力学不动 |
| **学习型流场** | `CurrentField.velocity_at()` | 新实现返回 `[vx, vz]` | Physics 不动（它只调接口） |

**这些插槽之所以能用，是因为每个都只有 1–3 个方法**。这是"窄接口"的直接收益：加算法不需要改流程。

但要提醒三件事：

1. **换规划器不会自动改善闭环**。S4 的 C 路径就是证据：几何更好、闭环更差。所以任何新规划器都必须跑同一套 18/45 矩阵。
2. **换控制器要保持"广义力"语义**。MPC 若直接输出推进器推力，就绕过了分配器，`M/X` 保比性质消失。
3. **RL 的输出必须过速率限制**。学出来的策略天然会输出跳变指令，而 G12 的 `Δψ ≤ 0.01 rad/步` 是硬约束。

### 1.4 三件"看起来小、实际大"的事

**(a) 三维环境**

现在 `WorldModel.segment_clearance` 是二维的。三维不是"加一个 z 分量"，而是要回答：

- 障碍是柱体（`z` 无限延伸）还是实体？
- 艇体外形是球、胶囊、还是网格？
- "扫掠体"在三维怎么定义（螺旋扫掠？）

**(b) 动态障碍**

`OccupancyGrid` 在构造时一次性算完 `occupied`，隐含假设"环境静止"。支持动态障碍需要：

- 时间维栅格（4D A*）或滚动重规划；
- 安全性判定从"静态段检查"变成"时空管检查"。

**(c) 真实艇参数辨识**

`uuv_3dof_synthetic_v1` 明确标注 test-only。真实艇需要 `m, I_y, A_u, A_w, A_q, D_L, D_Q, k_θ` 的辨识，而 `k_θ` 现在是集总系数——真实艇的恢复力矩来自重心/浮心几何，不能用一个 `sinθ` 系数替代。

### 1.5 论文还缺什么（C6）

| 缺项 | 现状 |
|---|---|
| 干净环境复现 | 有命令清单，未在全新机器上执行 |
| 可移植发布包 | 无闭包（依赖、运行文件、路径） |
| 最终图表 | 有 dashboard / viewer，缺论文级排版 |
| 完整正文 | 有 20+ 篇技术文档，未合并 |

**这四项不影响已有结论的有效性，但影响可复现性主张**。这也是为什么文档反复写"最低交付尚未完成"。

### 1.6 方法论本身能不能搬走

这个项目最可迁移的不是算法，是**四条纪律**：

| 纪律 | 具体做法 | 迁移到别的项目 |
|---|---|---|
| **时间纪律** | `dt` 固定、`t+dt` 断言、seq 单调 | 任何实时/半实时闭环 |
| **证据分层** | Python / 真实 / 联合，各自标支撑域 | 任何"仿真→实机"研究 |
| **不可变证据** | frozen dataclass + manifest + SHA256 | 任何需要审计的实验 |
| **显式失败** | 12 态枚举 + 分类学 + "不启动"也是证据 | 任何要写失败分析的报告 |

其中**"不启动也是证据"**这一条最少见也最有用：强流三项不是"跑了失败"，而是"Python 先失败 → 门禁拒绝 → 真实后端没启动"。这比"跑了但失败"更能说明系统的自我保护在生效。

## 2. 严谨版：学术总结

### 2.1 扩展点的类型学

把"加功能"分成三类，因为它们的代价差一个数量级：

| 类型 | 定义 | 例子 | 代价 |
|---|---|---|---|
| **替换实现** | 满足既有协议，不改任何契约 | RRT* 替换 A*；MPC 替换 PID | 低（局部） |
| **扩展契约** | 新增可选能力，旧实现仍有效 | `GuidanceController3DOF` 的加入 | 中（接口演进） |
| **改变契约** | 状态维度、坐标语义、安全定义变化 | 3-DOF → 6-DOF；二维 → 三维环境 | 高（协调迁移） |

**判据**：若新功能需要修改 `Core` 中任何 `to_numpy()` 的形状约定，则属于第三类，必须走"新增并行类型"而非"放宽既有断言"。

这与 README 的表述一致：

> This is a coordinated Core/Environment/Physics/Simulation migration, not a change that should be made by simply allowing larger arrays in the current 3-DOF classes.

### 2.2 6-DOF 的接口冲击分析

设当前契约为 `C_3 = (Core_6, Physics_{R^6→R^6}, Env_{xz}, Ctrl_{2×3})`，目标为 `C_6 = (Core_{12}, Physics_{R^{12}→R^{12}}, Env_{xyz}, Ctrl_{6×6})`。

| 契约 | 是否可复用 | 说明 |
|---|---|---|
| `Pose` / `Twist` 的 6 分量 | ✅ 已是 6 维 | 无需改字段，只需解除"非活跃分量为 0"的约束 |
| `VehicleState.to_numpy()` | ✅ 已是 12 维 | 无需改 |
| `Π` 投影与 `1e-12` 断言 | ⚠️ 需参数化 | 从"硬编码 6 维"改为"由后端声明活跃索引集" |
| `Integrator` 协议 | ❌ `shape=(6,)` 硬编码 | 需维度感知或并行 6-DOF 类型 |
| `Unit` 选择矩阵 `S` | ❌ `diag(1,0,1)` | 6-DOF 需完整 6×6 分配矩阵 + 执行器模型 |
| `segment_clearance` | ❌ 二维 | 需三维几何与扫掠体定义 |
| `Navigator` 安全判定 | ⚠️ 结构可留、谓词要换 | 碰撞/边界谓词从二维升三维 |
| `ControlInput` 语义 | ✅ 广义力 | 语义不变，只是维度用满 |

**关键观察**：`Core` 几乎不用改（它一开始就是 6 分量设计），真正要改的是 **`Integrator` 的形状假设**与 **`Environment` 的维度**。这说明"Core 保持 6 维"这个早期设计决策在 6-DOF 迁移时回收了收益。

### 2.3 研究方法的可迁移性论证

本项目的证据体系可抽象为一个四元组：

```
ResearchArtifact = (Claim, Evidence, Provenance, Scope)
```

| 元素 | 本项目实现 | 一般化要求 |
|---|---|---|
| `Claim` | "控制器在定常流下保持 RMS ≤ 0.35 m" | 可判定、可量化 |
| `Evidence` | `E_P / E_R / E_J` | 每条 claim 至少一条直接证据 |
| `Provenance` | release + manifest + SHA256 + source snapshot | 可追溯到代码版本 |
| `Scope` | 场景/流/初始态/载具/环境 | 显式列出未覆盖维度 |

**可迁移性命题**：任一"仿真→实机"研究，若满足上述四元组且 `support` 关系显式声明，则其结论的可信度可被第三方独立复核，而不依赖作者自述。

**但有一个前提**：`Scope` 必须包含"实验因子是否真的生效"的检查。本项目的 F2 就是反例——标签写"实测流"，实际流幅值仅为 F1 的 0.7%。**这提示了一个通用检查项：任何"因子 A 生效"的主张，都必须附带 A 的实际作用量测量**（这里是 `max|c(t)|`），而不只是配置标签。

这条可以写成方法论贡献：**配置标签 ≠ 因子生效**，需要"作用量证据"（dose evidence）。

### 2.4 三条性质 + 三条纪律（全系列收束）

**三条架构性质**（第 1 段）：

1. **子空间嵌入**：`Π: R^12 → R^6` 是坐标投影，非近似 ⇒ 3-DOF 结果可无损嵌入 6-DOF。
2. **单向依赖 + 结构协议**：DAG 依赖 + `Protocol` ⇒ 替换实现不需改流程。
3. **两栈同构**：`π_A = π_B ∘ ψ` ⇒ Python 结果对真实链路有（必要非充分）预测力。

**三条工程纪律**（贯穿 06–07）：

1. **时间纪律**：`dt` 固定、`t_{k+1} = t_k + dt` 断言、`seq` 严格递增 ⇒ 可复现。
2. **证据分层**：每条主张标注支撑域 ⇒ 不夸大。
3. **显式失败**：12 态枚举 + 分类学 + "不启动"也是证据 ⇒ 失败可归因。

**这三条性质解释了"为什么这套代码能支撑论文"，三条纪律解释了"为什么它的结论可信"。** 二者缺一，都是"跑通了很多工况"而非"建立了可复核的知识"。

### 2.5 最终局限（按对结论的影响排序）

| # | 局限 | 影响的结论 |
|---|---|---|
| 1 | F2 实测流在任务窗口内几乎未生效（0.35 mm/s） | "实测流鲁棒性"不可声称 |
| 2 | 安全为事后判定，非预测式约束 | "通过验收"≠"安全" |
| 3 | 参数为合成值，无辨识 | 不能外推到真实艇 |
| 4 | 二维、静态环境 | 不能外推到三维/动态 |
| 5 | 强流仅 Python 拒绝 | "强流不可行"是 Python 结论 |
| 6 | 真实矩阵有未归因失败（S1/F1/P4） | 不能声称"零故障" |
| 7 | 无统计检验（重复 2–3 次） | 不能声称"统计显著" |
| 8 | 无干净环境复现包 | 可复现性主张受限 |
| 9 | 相机视频黑帧 | 视觉证据只有查看器 |
| 10 | 恢复力矩为集总系数 | 不能讨论稳心高度/横滚稳性 |

### 2.6 下一步的优先级（按投资回报）

| 优先级 | 工作 | 理由 |
|---|---|---|
| P0 | 修正 F2 的 gate 中心或延长任务 | 让"实测流"因子真正生效，成本最低、收益最大 |
| P1 | 干净环境复现包 | 直接补 C6 缺口，且不涉及算法风险 |
