## 1. 通俗版

### 1.1 制导要回答的三个问题

规划给出的是**折线**（一串航点）。船不会"瞬移"到折线上，也不会严格沿折线走。制导要回答：

| 问题 | 机制 | 输出 |
|---|---|---|
| 我该朝哪看？ | 前视点（lookahead） | `pitch_ref` |
| 我走到路径的哪一段了？ | 进度投影 | 标量 `s` |
| 什么时候交给下一阶段？ | 终端移交条件 | `terminal_ready` |

### 1.2 LOS 的直觉：开车看前方 30 米，而不是看车头

如果控制目标是"车头对准路径上的最近点"，会出问题：车稍微偏离，最近点就在正侧方，船就会**横着猛打方向**，然后冲过路径、再反向修正，来回摆。

正确做法是看**前方一段距离的点**：

```
p_target = 路径上 (当前进度 s + 前视距离 Δ) 处的点
pitch_ref = atan2(z_target − z, x_target − x)
```

这样产生自然的"回正"作用：偏左了，前视点在右前方，船会平缓地转回路径；偏得越多，横向分量越大，修正越强。这就是经典的"比例导引/LOS"思想。

**前视距离 Δ 的权衡**（这是本段最重要的工程判断）：

| Δ 太小 | Δ 太大 |
|---|---|
| 频繁小幅修正，轨迹锯齿状 | 抄近路、切内角，可能撞障碍 |
| 抗扰好，但抖 | 平稳，但偏离路径远 |

本项目取值：A 栈 `Δ = 0.5 m`（航速 0.3 m/s），G12 `Δ = 2.3 m`（航速 0.48 m/s）。
直觉上 Δ 应与"转一个弯需要的前进距离"同量级，随速度增大。

### 1.3 进度投影：把"我在哪"压成一个标量

路径是折线，用**弧长** `s` 标记位置：`s ∈ [0, L]`。

问题：怎么从当前位姿算出 `s`？

做法是"找最近点"：

1. 把位置投影到当前段上，得到 `μ ∈ [0,1]`（段内比例）、`s = c_i + μ·L_i`
2. 计算沿轨误差 `e_along` 与横向误差 `e_cross`
3. 取所有候选段里"距离最近"的那个

听起来简单，但直接这么写会**抖**。原因有三：

**(a) 折角处会跳**：船在两个段交界附近，稍微动一下，"最近段"就从 i 跳到 i+1，`s` 会突变。

**(b) 平行段会误跳**：如果有两条平行路径段（比如绕过去再绕回来），"最近段"可能跳到远处那一条。

**(c) 倒着走会倒退**：船被流推回去，`s` 变小，前视点往回退，控制器就会"往回追"，形成振荡。

### 1.4 四个防抖机制（这是本段最精巧的部分）

项目用四个约束把 `s` 钉住：

| 机制 | 参数 | 作用 |
|---|---|---|
| **顶点门**（gate） | `switch_radius = 0.2 m` | 必须靠近 `p_{i+1}`，或"越过终点且横向误差小"，才允许进入第 i+1 段 |
| **前向窗口** | `forward_window = 2.0 m` | 只看 `s + 2 m` 以内的段，远处分支不可能被选中 |
| **位移夹紧** | `progress_slack = 0.05 m` | 每步 `s` 最多前进"本步实际位移 + 5 cm"，防止瞬移 |
| **单步切换上限** | `max_switches_per_step = 3` | 一步最多连切 3 段，防止"一步跳到终点" |

顶点门的半径还带自适应：

```
r_i = min(0.2, 0.45·L_i, 0.45·L_{i+1})
```

为什么要乘 0.45？因为如果段很短（比如 0.1 m），0.2 m 的门会跨到隔壁段去。取 45% 保证门永远不越过本段的两个端点——这叫"管道条件"（tube condition），防止"船虽然在路径外很远，但因为越过了终点平面就被判定进入下一段"。

**单调性**是最终的保险：

```
committed_s = max(前一步的 committed_s, 本次投影 s)
```

即使投影因为抖动给出了更小的 `s`，提交值也**绝不后退**。这就是"迟滞"（hysteresis）的作用：允许"跳过头"，不允许"往回退"。

### 1.5 为什么单调性这么重要

因为前视点是 `s + Δ`。如果 `s` 会后退，前视点就会后退，控制器就朝后飞——而船的唯一推力是向前的，结果就是"船在原地打转，找不到方向"。

代码里甚至专门统计了这个指标：

```
progress_monotonicity_violations = #{s_{k+1} < s_k}
```

验收要求它必须为 0。

### 1.6 G12：把 LOS 从"能走"提升到"能贴着走"

G12 是 B 栈的制导内核（[feasible_v2/guidance.py](../../ros2/twin_axial_feasible_v2/guidance.py)），在 LOS 基础上加了四件事：

**(a) 预瞄弯道减速**

```
取 s 到 s+2 m 之间的 12 个切向角，bend = max − min
速度 = v_turn + (v_cruise − v_turn)·max(0, 1 − bend/0.35)
```

即：前方 2 m 内弯得越厉害，越慢。`v_turn = 0.10`、`v_cruise = 0.48`。
为什么需要？因为 UUV 转得慢，等看到弯再减速就来不及——会切角或者撞内壁。

**(b) 电流与侧滑补偿**

```
χ = atan2(target − pos)          ← 期望的地面航迹角
pitch = χ + atan2(w_c + w_res, max(0.08, u))
```

即将"朝目标的方向"加上"水流和侧滑造成的横向漂移"的补偿角。`max(0.08, u)` 是防止低速时除零爆炸。

**(c) 发射对齐（ARMING → ALIGN → TRACK）**

前 2 s 速度强制为 0，只允许转姿态。当 `|pitch − θ| ≤ 5°` 且 `|q| ≤ 0.05` 并保持 0.5 s，才"放行"速度。

为什么？如果初始俯仰角是 0，但路径要求低头 30°，你如果一开始就给推力，船会先**水平冲出去一段**（`u·t`），再开始下潜。这段漂移在狭窄场景里就是撞墙。

**(d) 速率限制**

```
Δpitch ≤ 0.20 × 0.05 = 0.01 rad/步
Δspeed ≤ 0.02 × 0.05 = 0.001 m/s/步
```

参考信号本身不能跳变。因为控制器会把"参考跳变"变成"力矩尖峰"，进而激励未建模动态。

### 1.7 三种终端策略，各治一种病

这三个策略都是**可选**的（`None` 就退回默认行为），因为它们是"实验性候选"，不是基线。

| 策略 | 治什么病 | 机制 |
|---|---|---|
| `ControlledStartupPolicy` | 初始姿态不对，一给推力就漂 | 制动 → 转首向 → 合格后**释放参考时钟** |
| `TerminalCapturePolicy` | 到终点速度不为 0，冲过头 | BRAKE → ALIGN → MOVE 状态机 |
| `TerminalApproachPolicy` | 不知道"现在开始刹车还停不停得住" | 影子控制器 roll-out 预测 6 组候选 |

**(a) 启动策略**

难点：参考轨迹是"从 t=0 开始走"，但船可能还停着、姿态还不对。如果照参考走，前几秒就是"用力追一个跑掉的参考"。

解法：**暂停参考时钟**。

```
startup_delay += dt      # 每步累加
参考时间 = 实际时间 − startup_delay
```

这样参考"等你准备好"再开始。约束是：预算 20 s、漂移 ≤ 0.10 m、实际俯仰 ≤ 75°、角速度 ≤ 0.35 rad/s。

**(b) 捕获策略**

到终点附近，LOS 还在说"朝前飞"，但速度不为 0 就会冲过去。捕获策略是一个显式状态机：

```
BRAKE → (速度≤0.03 且 |q|≤0.03) → 选修正方向（两个方向取进展大的）
      → ALIGN → (|Δψ|≤0.08) → MOVE（3 s @ 0.08 m/s）→ BRAKE → …
```

最多 6 次尝试，预算 60 s。每次修正段都要通过碰撞检查，且必须"朝目标方向有正进展"。

为什么"先刹车再转"？因为转弯需要时间，带着速度转弯会画出大弧线，冲出边界。

**(c) 接近策略（最有意思的一个）**

问题：在离终点 4 m 处，你怎么知道"现在以 0.15 m/s 前进、0.35 m 处开始刹车"能不能停住？

解法：**用影子系统做 roll-out 预测**。

```
每 2 s 评估一次（最多 16 次）：
  对 3 个速度 × 2 个刹车距离 = 6 组候选：
      复制当前控制器（含积分记忆）+ 复制物理引擎
      前向仿真最多 30 s，用与真实执行**完全相同**的反馈核
      若某步同时满足：
          - 预测轨迹的净空 ≥ 要求 + 5 mm
          - 不越过终点平面
          - 进入"可移交"条件（速度/角速度/俯仰误差）
      → 选中该候选，切换为"执行预测轨迹"
```

关键设计：**执行阶段仍然用实时反馈，而不是回放预测的控制量**。预测的作用只是"证明这条路存在"，实际飞行时每步都校验：

```
max|state − predicted| ≤ 1e-6  否则 APPROACH_PREDICTION_DEVIATION
```

这是一种"预测-校验"（predict-then-verify）结构：预测给出可行性证书，执行时监控偏差，偏差超限就失败退出，而不是硬着头皮走。

它的作用有多大？在零流 P1 的 12 场景固定套件上：

| 终态 | P1（无接近策略） | P1 + approach |
|---|---|---|
| SUCCESS | 7 | **10** |
| CAPTURE_FAILED | 2 | **0** |
| TIMEOUT | 1 | **0** |
| COLLISION | 2 | 2 |

即"把 2 次捕获失败 + 1 次超时变成了成功"，碰撞数不变。这不能说"更安全"，只能说"更少卡在末端"。

### 1.8 导航状态机：`guidance_phase`

一段任务里，`guidance_phase` 只会是这五个之一：

```
TIMED_REFERENCE → STARTUP → PATH_FOLLOWING → TERMINAL_APPROACH → TERMINAL_CAPTURE
```

优先级（每步判定顺序）：

```
STARTUP  >  TERMINAL_APPROACH  >  TERMINAL_CAPTURE  >  PATH_FOLLOWING  >  TIMED_REFERENCE
```

**关键约束：一旦进入终端，就不再更新进度投影**（`capture_latched` 之后跳过 LOS）。因为终端阶段已经不需要"我在路径哪里"，继续更新反而会因为原地转圈而让 `s` 抖动。

### 1.9 失败要分类，不能都叫"没成功"

`NavigationStatus` 里的终端相关失败有三种，含义完全不同：

| 状态 | 含义 | 说明什么 |
|---|---|---|
| `STARTUP_FAILED` | 连初始姿态都没摆好 | 起始条件与任务不匹配 |
| `APPROACH_FAILED` | 找不到能停住的候选 | 末端几何/速度不可行 |
| `CAPTURE_FAILED` | 停住了但靠不上目标 | 末端控制权限不足 |

加上 `COLLISION`、`OUT_OF_BOUNDS`、`TIMEOUT`，一共 6 种"没成功"的理由。
论文里能据此说清"失败在哪个环节"，而不是笼统的"成功率低"。

## 2. 严谨版：学术总结

### 2.1 进度投影的形式定义

设折线 `P = {p_0, …, p_m}`，段长 `L_i = ‖p_{i+1} − p_i‖`，累计弧 `c_i = Σ_{k<i} L_k`，总长 `L = c_m`。

段 `i` 上的位置投影（无裁剪参数 `λ`，裁剪后 `μ`）：

```
t_i = (p_{i+1} − p_i)/L_i
λ_i = ⟨P − p_i, t_i⟩ / L_i
μ_i = clip(λ_i, 0, 1)
q_i = p_i + μ_i L_i
s_i = c_i + μ_i L_i
e_along,i = ⟨P − q_i, t_i⟩
e_cross,i = ⟨P − q_i, n_i⟩,   n_i = (−t_{i,z}, t_{i,x})
```

### 2.2 门控函数与准入域

```
r_i = min(r_cfg, 0.45 L_i, 0.45 L_{i+1})
G(i) = [ ‖P − p_{i+1}‖ ≤ r_i ]  ∨  [ λ_i ≥ 1 ∧ |e_cross,i| ≤ r_i ]
```

准入段上界由顺序门与窗口共同决定：

```
a_k = max{ a : G(k) 对所有 k ∈ [a_active, a−1] 成立,  a − a_active ≤ N_switch,  c_{a+1} ≤ s_prev + W }
```

其中 `N_switch = 3`、`W = 2.0 m`。

**性质（可靠性而非完备性）**：门控只保证"不误跳"（不会从非相邻分支打开远端段），**不保证"必跳到"**——若一步内门未全部打开，切换被推迟到后续步，并置 `switch_limit_reached`。

### 2.3 最近投影与字典序打破平局

```
i* = argmin_{i ∈ [a_active − 1, a_k]} ( ‖P − q_i‖, s_i, i )
```

三元组字典序：先比距离，距离相等取更小弧长，再相等取更小索引。这消除了浮点并列导致的非确定性。

### 2.4 单调提交与双夹紧

```
s_desired = max(s_prev, s_{i*})
s_commit  = min( s_desired,  s_prev + W,  s_prev + ‖P − P_prev‖ + ε )
```

其中 `ε = progress_slack = 0.05 m`。

**命题（单调有界）**：`s_commit` 关于步数非减且 `s_commit ∈ [0, L]`。

*证明要点*：`s_desired ≥ s_prev` 取最大；`s_commit` 的两项上界均 `≥ s_prev`（因 `W > 0`、`‖ΔP‖ + ε ≥ 0`）；上界 `L` 由 `s_prev ≤ L` 与窗口定义保证。∎

**推论**：`segment_index` 单调不减（提交段仅在 `c_{i+1} ≤ s_commit` 时前进），故不存在"回退到前一段"的行为。

双夹紧的物理意义：`W` 限制"能看多远"，`‖ΔP‖ + ε` 限制"一步能走多远"。后者是对**物理可达性**的约束——即使投影显示 `s` 前进了 10 m，若船实际只移动了 0.05 m，提交值也只能前进 0.05 m。这防止了"路径自交时投影跳到远端"这一类拓扑歧义。

### 2.5 LOS 律及其几何性质

```
s_target = min(s_commit + Δ, L)
p_target = p_i + μ L_i,  其中 s_target ∈ [c_i, c_{i+1}]
ψ_ref = atan2(p_target,z − P_z,  p_target,x − P_x)
```

**与无限线 LOS 的差异**：经典 `LOS_χ` 使用"到无限延长线的横向误差"构造 `χ_ref = χ_path − arctan(e_cross/Δ)`，对直线段等价；本项目直接取**有限折线上的前视点**，因此在折角附近，前视点可能落在**下一段**，指令会跨越拐角形成"弦"（chord）。

**已知后果**：

1. 可能切内角，**不具备碰撞感知**；安全性完全依赖执行后的 `segment_clearance` 检查。
2. `ψ_ref` 在拐角处可以跳变；本项目通过 `pitch_rate_ref = 0`（不声称微分一致）与显式统计 `maximum_pitch_reference_step` 来处理，而不是平滑它。

**为什么不做变前视**：规范明确"v1 只用一个显式配置的固定 `Δ`"，以避免"调参调出来的鲁棒性"。这是一个**可归因性**选择。

### 2.6 终端移交条件

```
terminal_ready = (segment_index = m−1)
              ∧ (L − s_commit ≤ d_entry)
              ∧ (‖P − p_m‖ ≤ d_entry)
```

`d_entry = 0.25 m`，且必须 `≥ goal_position_tolerance`（构造期断言）。

**语义**：`terminal_ready` 只表示"**有资格**移交"，不表示"成功"。成功由 `arrived()` 三条件 + `settle_time` 判定。这一区分防止"进入终端阶段"被误报为"到达"。

### 2.7 G12 制导的速率与几何约束

```
bend = max_{k} χ_k − min_{k} χ_k,   χ_k = 切向角 @ s + k·(2.0/12)
v_ref = v_turn + (v_cruise − v_turn)·max(0, 1 − bend/0.35)
ψ_ref = χ_target + atan2(w_c + w_res, max(0.08, u)),   |ψ_ref| ≤ 70°
Δψ_ref ≤ 0.20·h,   Δv_ref ≤ 0.02·h    (h = 0.05 s)
```

发射约束：

```
t ≥ 2 s ∧ |ψ_ref − θ| ≤ 5° ∧ |q| ≤ 0.05 rad/s ∧ 持续 ≥ 0.5 s  ⇒  release
```

其中 `bend/0.35` 的归一化常数来自冻结的 12 组筛选（`G01…G12`，4 速度 × 3 前视），G12 为 `v_cruise = 0.48`、`Δ = 2.3`。

**注意**：`v_ref` 是**开环速度规划**，不是基于跟踪误差的减速。规范明确排除了"error-based slowdown"与"observer"。

### 2.8 三种终端策略的状态机与判据

**（a）启动**

```
BRAKE（u_ref = −clip(u, ±0.15)）→ 静默（‖ν‖≤0.03, |q|≤0.02）
      → ALIGN（ψ_ref 以 0.15 rad/s 斜坡趋近首向）
      → 合格（|Δψ|≤0.03 且保持 0.5 s）→ RELEASED（参考时钟启动）
```

约束：预算 20 s、漂移 ≤ 0.10 m、实际 `|θ| ≤ 75°`、`|q| ≤ 0.35`。
**核心机制**：`reference_time = t − startup_delay`，即参考时钟被"暂停"，而非重置控制器。

**（b）捕获**

```
BRAKE → (‖ν‖ ≤ 0.03 ∧ |q| ≤ 0.03) → SELECT
SELECT：对方向 d ∈ {+1, −1}，ψ = χ_bearing（d=+1）或 wrap(χ_bearing + π)（d=−1），
        构造 0.05…0.3 m 的局部段，要求 progress > 0 且 is_segment_valid
        取 (progress, −|Δψ|) 字典序最大者
      → ALIGN → (|Δψ| ≤ 0.08 ∧ |q| ≤ 0.03) → MOVE（3 s @ 0.08 m/s）→ BRAKE
```

预算 60 s、最多 6 次尝试。任一步超出 `|θ| > 70°` 或 `|q| > 0.35` 即 `FAILED`。

**（c）接近（采样式预测移交）**

```
触发：L − s_commit ≤ 4.0 m，且距上次评估 ≥ 2.0 s，且评估次数 < 16
候选：V = {0.15, 0.10, 0.05} × D_brake = {0.35, 0.20}  （6 组）
rollout：x_{k+1} = Φ_h(x_k, π(x_k, g(x_k)), ν_c(x_k, t_k), h)，最多 30 s
判据：净空 ≥ ρ + 5 mm ∧ 不越过终点平面 ∧ 进入可移交集
选中：冻结候选，保存预测状态序列 {x̂_k}
执行：每步要求 ‖x_k − x̂_k‖_∞ ≤ 1e-6，否则 APPROACH_PREDICTION_DEVIATION
```

**理论定位**：这是在有限候选集上的**可行性采样**（feasibility sampling），不是最优控制，也不是 reachability 分析。其保证是：

- **可靠性**：若预测通过且执行偏差 ≤ 1e-6，则实际轨迹与预测一致（确定性 + 相同反馈核）；
- **不完备性**：候选集外可能存在可行解；搜索耗尽返回 `APPROACH_UNKNOWN_SEARCH_EXHAUSTED`，语义是"未知"而非"不可行"；
- **域限制**：仅在零流下启用（`world.current ≠ 0 → APPROACH_OUT_OF_DOMAIN_CURRENT`），因为 `deepcopy` 的影子物理与真实流场不保证同步。

### 2.9 实验证据（固定套件，非普遍优越性）

| 对照 | 结果 | 边界 |
|---|---|---|
| LOS vs 匹配定时（16 场景 × 2 臂 × 2 重复 = 64 次） | SUCCESS 10 vs 9；COLLISION 1 vs 3；CAPTURE_FAILED 2 vs 1；STARTUP_FAILED 1 vs 1；OOB 2 vs 2 | 两臂内环相同，差异归因于外环制导；**不是**"时钟 vs 无时钟"的纯效应 |
| P1 12 场景 ± TerminalApproach | SUCCESS 7 → 10；CAPTURE_FAILED 2 → 0；TIMEOUT 1 → 0；COLLISION 2 → 2 | 零流、0.2 m/s、固定路径；不更新 LOS 结果 |

速率包络违规：LOS 4/16 vs timed 3/16（独立诊断项，不与终态相加）。

### 2.10 局限

1. **LOS 无碰撞感知**：前视点可落在障碍另一侧，靠事后检查拦截。
2. **单调性以"跳过头"为代价**：若投影误判到远端，`s` 不会回退，只能靠 `max_switches` 与窗口限制其发生概率。
3. **固定前视**：`Δ` 不随速度/曲率变化（A 栈）；G12 有速度规划但仍非自适应前视。
4. **终端策略是候选而非基线**：默认 `None`，其结果不能并入基线成功率。
5. **接近策略域受限**：仅零流、仅 6 组候选、`deepcopy` 成本高（墙钟时间单独统计）。
6. **初始化不做重定位**：起点若已偏离路径较远，不会"吸附"到路径上（v1 明确不支持）。
