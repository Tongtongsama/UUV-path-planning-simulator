## 首个载具与输入决策

选择独立合成测试载具 `uuv_minimal_xdyn_v1`，不称为已验证 LRAUV 或 BlueROV2。
运动目标为纵向 x-z/pitch，动力学由 LOTUSim 接入的 xdyn 求解；必须明确是否运行全
6 自由度或使用经验证的约束，不能以每步强制归零非活动状态冒充物理约束。
现有 Python 合成参数只作为候选参考，需核对 xdyn 矩阵、阻尼及恢复力约定后单独配置。

执行器第一版采用理想推力源（N），不声称 RPM、电机、电调或真实推进器响应：

- 质心处前向推力 T_s，body +X 向前。
- 前后两处垂向推力 T_f、T_a，作用点 x=+l/-l，body +Z 向下。
- 几何关系 X=T_s，Z=T_f+T_a，M=l*(T_a-T_f)。
- 纯俯仰试验使用 T_f=-M/(2*l)、T_a=+M/(2*l)，净垂向推力为零。
- 明确位置、单位、单推进器限幅与是否允许反向；l 与限幅需在模型配置时固定。
- 这两个垂向推力源是理想可逆执行器，不代表现有 LRAUV 舵面。

理由：本地 lrauv.yml 只有 propeller 启用，舵面被注释，且螺旋桨参数注明有效范围问题。
BlueROV2_current_none.yml 注明其简化执行器不能独立控制 roll/pitch。不能直接假定两者
足以执行现有纵向控制任务。安装版本可能不同，实施前必须核对并固定实际 revision。

## 唯一状态所有权

Python 控制算法 → 有界执行器推力 → ROS VesselCmdArray → LOTUSim physics plugin
→ xdyn → Gazebo 状态 → 带仿真时间的状态反馈 → Python。

严禁在此载具上使用回放 MOVE、waypoint_follower 或 Python3DOFBackend 推进状态。
MAS 仅负责创建、删除和试验前初始化。状态重置只能发生在独立试验边界。

## 首先补齐反馈和时钟

本地 /lotusim/poses 只提供位姿，不能直接用于测量 surge 速度与 pitch 角速度。
优先在物理更新完成后发布 nav_msgs/Odometry（位置 ENU、机体 FLU 速度），
或定义同等明确的状态消息：实体名、序号、仿真时间、位置、四元数、速度、角速度。
反馈应来自求解器/Gazebo 物理状态，不以控制指令或显示插值代替测量。
动力学失败需标记状态无效/陈旧；不能给旧状态加新时间戳后继续闭环。

控制器使用反馈仿真时间差，不使用回放墙钟。重复时间不积分，时间倒退重置控制器，
时间跳跃/陈旧反馈触发明确的停机策略。Gazebo 暂停时不积累积分。
看门狗必须在控制进程之外（服务端）实施，客户端崩溃后仍可把执行器归零。
先固定 0.05 s 为候选联合步长，验证 xdyn 实际推进再决定控制频率；不沿用回放 0.2 s
的配置而默认其适用于控制。ROS /clock 发布路径也须实际验证，不能假定默认存在。

## 分阶段验收

1. 开环：无障碍、无流、无浪、深水、水平初始姿态。分别运行零输入、正/负前向
   推力脉冲、前后垂向推力差分脉冲、撤除输入。记录全部输入、状态、时间与求解失败。
   正向推力产生正向加速；正 M 与 nose-up 的符号经坐标转换实测核验。零输入不要求
   绝对静止，必须按所配置浮力/恢复力解释漂移。两个重复试验检查时间及结果一致性。
2. 速度：只闭合 surge PI，姿态目标保持水平；先验证输入限幅、反积分饱和与卸载。
3. 姿态：pitch PD/有界 PI 与速度环组合，测试小角度目标及回零，无障碍直航。
   目标、容差、观测窗、最大输入、最大姿态/深度范围在运行前写入配置，不事后放宽。
4. LOS：前三项通过后才接垂直平面路径；先直线/平缓路径，再考虑障碍场景。
5. TerminalApproach：模型失配、预测后端、执行器映射与运算时间明确后另行评估。
